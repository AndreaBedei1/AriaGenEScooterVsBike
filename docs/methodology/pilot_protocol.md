# Pilot protocol (feasibility study, 3 participants)

**Status: DRAFT for discussion with the project lead.** No acquisition may start before the
authorisations described in `docs/ethics/` are obtained, the route has been checked on site
(`docs/route/route_validation_checklist.md`) and a technical test recording has been made.
The pilot is a **feasibility study**: it does not test hypotheses and its results are not
generalisable.

## 1. Aims of the pilot

1. Verify the acquisition chain end to end: custom recording profile accepted by the device,
   all streams present (incl. GNSS, high-frequency VIO, hand tracking), battery and storage for
   the planned rides, transfer to restricted storage, extraction (`extract-aria`).
2. Quantify per stream and per ride: dropouts, gaps, timestamp problems, VIO validity and
   resets, gaze validity, hand-tracking coverage, GNSS fix and accuracy (`quality.json`).
3. Test route alignment (`map-segments`) and the segment/event annotation procedure.
4. Measure gaze accuracy outdoors (targets before/after each ride).
5. Evaluate hand tracking while riding (`hand_tracking_validation.md`).
6. Check repeatability between two rides with the same vehicle (if two trials per vehicle).
7. Estimate the variability of the core metrics (between participants, between trials, between
   vehicles, between segments) to size the main study.
8. Identify protocol problems (navigation, fatigue, glasses fit with helmet, safety, timing,
   weather), and decide whether a larger study is feasible.

## 2. Participants

- 3 adult volunteers (>= 18 years), able to ride a bicycle and an e-scooter safely, with some
  prior e-scooter experience (or a supervised practice session before the test day), normal or
  contact-lens-corrected vision (compatibility of Aria Gen 2 with spectacles to be checked).
- Coarse covariates (pseudonymous, no direct identifiers): age band, sex/gender (optional),
  riding frequency for each vehicle, years of experience, familiarity with the route area,
  vision correction, handedness.
- Exclusion: conditions that make riding unsafe, alcohol/drugs on the test day, inability to
  wear the glasses with the helmet comfortably.
- With N = 3 the pilot cannot estimate population effects; ideally the 3 participants differ in
  e-scooter experience to expose protocol problems.

## 3. Design

- Within-participant: every participant rides **both vehicles** on the **same route** in the
  **same direction** (route CES_A, desk draft; CES_B as alternative).
- **Repetitions are configurable** (`configs/protocol/pilot.yaml`, `plan-rides`):

| Option | Rides per participant | Order scheme | Pros | Cons |
|---|---|---|---|---|
| 1 trial per vehicle | 2 (about 40 min riding) | AB / BA alternating; with 3 participants 2 start with one vehicle and 1 with the other (imbalance reported) | short, low fatigue | vehicle confounded with order within each participant; no repeatability estimate; learning of the route falls on the first vehicle |
| **2 trials per vehicle (recommended for the pilot)** | 4 (about 80 min riding) | **ABBA / BAAB**: each participant's mean ride position is identical for both vehicles, so a linear learning/fatigue trend is balanced within every participant | within-person repeatability (trial 1 vs 2); order effects estimable; variance components for sizing | longer visit, fatigue; traffic and light change during the visit; possibly two visits |
| more trials | 6+ | ABBA blocks | better reliability estimates | fatigue, cost; not needed before the main study design |

  Default plan generated by `python -m ariagen_escooter plan-rides configs/protocol/pilot.yaml`:
  P001 E-B-B-E, P002 B-E-E-B, P003 E-B-B-E (E = e-scooter, B = bicycle). The first-vehicle
  imbalance (2 vs 1) is documented; with ABBA it does not bias the within-participant mean
  position.
- **One visit or two**: 4 rides in one visit need about 2.5-3 h including set-up, calibration,
  pauses and questionnaires. If fatigue or light changes are a concern, use 2 visits on
  different days with 2 rides each (`rides_per_session: 2`), at the same time of day.
- **Repeating the route does not repeat the traffic**: comparisons are made primarily on the
  same **infrastructure segments** (route-referenced), while spontaneous events (interactions)
  are analysed as events that may occur in one ride and not in another.

## 4. Factors controlled or recorded

| Factor | Control | Recorded where |
|---|---|---|
| Previous experience with each vehicle | inclusion + covariate | pre-test questionnaire (coarse categories) |
| Familiarity with the route | route briefing for all; ride order balanced | pre-test questionnaire; trial number / ride order |
| Order of vehicles | counterbalanced (ABBA/BAAB) | manifest `trial.ride_order` |
| Time of day | fixed time window (e.g. 10:00-13:00 or 14:30-17:30, avoiding rush hours and low sun) | manifest `timing` |
| Weather / road surface | ride only in dry conditions without rain forecast; abort rules | manifest `conditions` (per ride in the ride sheet) |
| Observed traffic | not controllable | ride sheet rating; exposure counts from video (planned) |
| Duration and interruptions | stopwatch + device times | manifest; `trimming.json`; ride sheet |
| Gaze quality | eye calibration in the companion app before each ride; validation targets before/after | ride sheet; validation files |
| VIO quality | device warm-up; record a short static period before departure | `quality.json` |
| Vehicle characteristics | same two units for all participants; settings fixed (e-scooter speed mode, saddle height adjusted and recorded) | manifest `equipment.vehicles[].characteristics` |
| Fatigue | pauses >= 10 min; water; post-ride fatigue item | post-ride questionnaire |
| Market days and events in the centre | avoid Wednesday and Saturday mornings | planning |

## 5. Procedure (one visit with 4 rides)

1. **Before the visit**: route checked on site; vehicles inspected (brakes, tyres, lights,
   e-scooter indicators, contrassegno and insurance valid; bicycle lights/bell); glasses charged
   and cleaned; storage free; weather checked; recording profile verified on a test recording.
2. **Arrival (about 25 min)**: information and consent (separate document, stored outside the
   repository); pseudonym assignment; pre-test questionnaire; safety briefing (ride as usual,
   respect the Highway Code, no instructions to perform any manoeuvre, stop whenever unsure);
   helmet fitting with the glasses; route briefing with a printed map and photos of key points.
3. **Familiarisation (about 10 min)**: short practice on both vehicles in a quiet area of the
   campus (not analysed), in the order of the first test ride.
4. **Each ride (about 20-25 min)**:
   - start recording; 30 s standing still (VIO initialisation, static reference);
   - gaze validation: look at the printed targets (2, 5, 10 m) for 3 s each;
   - ride the route (researcher following at a safe distance on a bicycle, giving only
     standardised navigation cues at predefined points if needed);
   - at the end: 30 s standing, repeat the gaze-validation targets, stop recording;
   - ride sheet: start/end times, weather, surface, traffic rating, incidents, deviations,
     navigation cues given, technical issues;
   - post-ride questionnaire (about 3 min).
5. **Pauses** of at least 10 minutes between rides; check glasses fit and battery; copy the VRS
   to the encrypted laptop at least after rides 2 and 4.
6. **End**: post-test questionnaire; debriefing.

**Abort / stop rules**: rain or wet surface, poor light, participant discomfort or fatigue,
glasses or helmet problems, vehicle defects, unsafe traffic situations, any request by a
participant or by a bystander (recording is stopped). Aborted rides are kept and documented,
never silently discarded.

## 6. Questionnaires (short)

**Pre-test** (once):
1. Age band (18-24, 25-34, 35-44, 45-54, 55+).
2. Bicycle use: days per week in the last 3 months (0, < 1, 1-2, 3-4, 5+); years of regular use.
3. E-scooter use: same categories; own vs shared.
4. Familiarity with the route area (1 = never been there ... 5 = daily).
5. Vision correction (none / contact lenses / other); handedness.
6. Sleep and well-being today (1-5, single item) - only to document unusual states.

**Post-ride** (after each ride, < 3 min):
1. Perceived safety overall (1-7) and on: cycle paths, shared paths, roads with traffic,
   crossings/roundabouts (1-7 each).
2. Perceived workload: raw NASA-TLX (6 items, 0-100) - optional if time is short; otherwise a
   single overall workload item (1-7).
3. Comfort of the vehicle and of the glasses with the helmet (1-7).
4. Physical effort (Borg CR10).
5. Anything unusual during the ride (free text, no personal data of others).

**Post-test** (once): preferred vehicle for this route and why (free text); perceived
differences in attention between vehicles (1-7 + free text); discomfort caused by the glasses.

## 7. Data flow

Raw VRS -> encrypted restricted storage (`data/raw/`, never versioned) -> EgoBlur-anonymised copy
for any viewing -> `extract-aria` -> `validate` -> `map-segments` (review) -> annotations ->
`run` -> `aggregate`. Details: `docs/privacy_pipeline.md`, `docs/data_schema.md`.

## 8. Feasibility outcomes and criteria for the main study

Report, per stream and per vehicle: completeness (rides with all core streams), dropout and gap
distributions, VIO valid fraction and resets, gaze valid fraction and measured accuracy,
hand-tracking detection rate, GNSS fix rate, share of route segments recovered by
`map-segments`, annotation agreement, time and effort per ride, adverse events and protocol
deviations, participant burden. Use the pilot data to estimate variance components of the core
metrics (participant, vehicle x participant, trial, segment) and to run simulation-based power
analyses for the main study (`statistical_analysis_plan.md`). Go/no-go criteria (to be agreed):
e.g. >= 90 % of rides with usable gaze and VIO on >= 80 % of the route; no safety incident;
participant burden acceptable.
